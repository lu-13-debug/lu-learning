# 零售门店销售日报与异常分析

这是一个可在约 10 分钟内讲清楚的小型行业练习：用 Python 标准库生成可复现模拟销售流水，用 SQLite 汇总门店日报、期间排名和销售占比，再用历史中位数标记销售下滑。

**所有数据均为模拟数据。异常由程序主动注入，只验证规则能否检出预设变化，不代表真实经营发现，也不能据此声称带来业务收益。**

## 快速运行

在作品集仓库根目录执行，需要 Python 3.10 或更高版本，不需要安装第三方包：

```powershell
python retail-mini/run.py
python -m unittest discover -s retail-mini/tests -v
```

打开 `retail-mini/reports/retail/report.html` 即可查看报告。HTML 内嵌 SVG 与样式，不依赖联网、数据库服务或前端构建。页面中的 CSV 下载链接需要与报告保存在同一目录。

## 练习回答什么问题

- 每家门店当天卖了多少钱、多少件，与昨天相比怎样？
- 期间销售额在门店之间如何分布？
- 哪个门店日期明显低于近期水平，值得进一步核查？

## 数据和指标口径

固定随机种子 `20261012`，覆盖 2026-01-01 至 2026-03-01，共 8 家门店、60 天、12 个 SKU、5,760 行流水。每行代表一个门店在某日期某 SKU 的销售汇总，不是顾客订单，也没有客户信息。

| 字段 | 含义 |
| --- | --- |
| `date` | 销售日期，ISO 格式 |
| `store_id` | 模拟门店编号 S01–S08 |
| `sku` | 模拟 SKU 编号 SKU01–SKU12 |
| `qty` | 非负整数销量 |
| `unit_price_cents` | 单价，整数分 |

金额采用整数分，销售额为 `SUM(qty * unit_price_cents)`，避免浮点累计金额误差；HTML 为方便阅读显示元。门店期间排名使用 SQL `RANK()`，占比以全门店期间销售额为分母。

日环比为 `(当天销售额 - 昨天销售额) / 昨天销售额`。SQL `LAG()` 取前一条记录后再检查是否为相邻自然日；缺少昨天或昨天为 0 时返回 NULL，CSV 留空，而不是输出无穷值或把缺失日期补成 0。

异常基线是同店**过去 7 个完整自然日**销售额的中位数，不包含当天。任意日期缺失则基线不可用；首 7 天不会误判。正基线下，当天金额严格低于基线 60% 才标记。基线为 0 时不做异常判断。

## 输出文件

所有产物位于本项目 `reports/retail/`，运行会重新生成这些固定文件：

| 文件 | 用途 |
| --- | --- |
| `sales.csv` | 可追溯的模拟 SKU 流水 |
| `daily_report.csv` | 每日门店销量、金额、环比、基线、比例和异常标记 |
| `store_ranking.csv` | 期间门店销售排名与占比 |
| `anomalies.csv` | 异常门店日期明细，保留全部日报字段 |
| `metrics.json` | 数据规模、对账指标、随机种子与注入信息 |
| `report.html` | 自包含图表报告：S03 趋势、排名、异常和口径 |

SQL 位于 `sql/daily_report.sql` 和 `sql/store_ranking.sql`。数据清洗、计算和导出入口是 `run.py`。测试写入本项目固定 `_tests_runtime` 目录，并只清理自己生成的六个文件。

## 验证与复核

先编写 9 项已知结果测试，在实现不存在时运行观察到 9 项失败，再实现并运行到 9 项全部通过。测试包括整数金额及 SQL 汇总对账、日环比、零分母、缺日窗口、首 7 天、正常及临界阈值、注入异常、可复现性和导出一致性。该流程记录的是“先有测试再实现”，最初红灯来自缺少入口实现。

手工复核异常：筛选 `sales.csv` 中 `date=2026-02-14, store_id=S03` 的 12 行，汇总 `qty × unit_price_cents`；再分别求 02-07 至 02-13 的每日金额并取中位数，对照 `anomalies.csv`。每个门店日期都可用同样的方法追溯。

## 面试讲解顺序（约 10 分钟）

1. 1 分钟：说明这是模拟零售日报练习，先讲业务问题和数据边界。
2. 2 分钟：解释 SKU 流水、整数分与 SQL 汇总；展示金额对账。
3. 2 分钟：展示窗口函数计算环比，说明缺日与零分母处理。
4. 3 分钟：展示 7 日中位数规则和 S03 下滑，手工复核异常金额。
5. 2 分钟：说明测试和局限，讨论接入真实数据后的改进。

## 局限与下一步

本练习未模拟星期差异、节假日、促销、退货、停业、客流和库存。60% 阈值是演示设定，没有通过标注样本调优。真实应用需要先做营业日和数据完整性校验，再对比同星期或分门店基线、回测误报和漏报，并让业务人员核查异常原因。缺少日期的门店日报不会自行补齐，因此不能将“无记录”解读为“零销售”。

可用于简历的事实表述：**基于 Python 与 SQLite 完成零售日报模拟练习，汇总 8 家门店 60 天的 5,760 行 SKU 流水，输出 480 条门店日报；实现日环比、销售排名和过去 7 日中位数异常规则，通过 9 项口径与边界测试，并生成可追溯 CSV 和 HTML 报告。**
